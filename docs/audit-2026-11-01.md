## Verified: what exists and works

- **Stack (unchanged):** React 18 + Vite 5 + TS strict + Tailwind 3 +
  Lucide frontend; FastAPI + Pydantic v2 backend. No database anywhere
  — reports live in browser localStorage only (`gaplens.workspace.v2`).
- **Routes (client pushState, SPA fallback on Vercel):** `/` landing,
  `/dashboard` home, `new-research`, `my-research`, `gaps`,
  `conflicts`, `graph`, `freshness`, `checklist`, `sources`,
  `reports`, `settings`. All dashboard pages render from one saved
  report; no decorative buttons found — every CTA navigates or acts.
- **Backend endpoints:** `GET /`, `GET /api/health` (boolean-only
  `groq_configured`), `GET /api/sample`, `POST /api/fetch`,
  `POST /api/analyze` (live + labelled `offline_sample` demo).
- **Engine (deterministic, 69 tests passing):** token-overlap coverage
  (covered ≥0.50, partial ≥0.25 with ≥2 matched terms, tight synonym
  pairs, plural stemming); numeric conflicts (money/percent/year/date/
  bare numbers — CGPA 7.0 vs 7.5 verified live 1 Nov) and stance
  conflicts, always labelled "possible" with both quotes; freshness
  (stale >365 days, undated never guessed); trust-tier alert (no
  official source → summary sentence + high-priority action);
  gaps (unanswered/partial/single-source/stale-only/undated-only);
  ranked verify-next actions; final validation sweep drops any quote
  that is not a verbatim substring of its source.
- **Fetching:** SSRF-safe (http(s) only, blocked hosts/suffixes,
  literal + DNS-resolved IP checks, redirect re-validation, max 3
  hops, 10 s timeout, 1 MB cap, 5 concurrent workers, per-source
  failure isolation). Rate limits fetch 60/min, analyze 30/min per IP
  (per-process only — resets on restart). Security headers set.
- **AI use (honest scope):** Groq, when a key is configured, receives
  ONLY the goal and returns ONLY proposed questions (≤8, strict JSON,
  any failure → template questions). Source text, URLs and pasted
  content never leave the server; no LLM output ever becomes a finding.
- **Frontend honesty features:** demo banner, "Backend connected /
  offline" header, coverage bar with "not a confidence score" wording
  in dashboard home, print/JSON export, theme persisted, skip link,
  mobile nav with focus trap + Escape, visible focus rings.
- **Live pair (verified 31 Oct–1 Nov):** Vercel `gaplens`
  (gaplens-omega.vercel.app) + SnapDeploy `gaplens-backend-77c25`,
  CORS exactly the frontend origin, auto-deploy on push.

## Preserve (do not break)

Name, branding, API shapes, deterministic engine, quote validation,
SSRF guards, demo labelling, local-only storage, Groq-questions-only
rule, ₹0 hosting, git identity Aarya Patel.

## Improve (P1, this redesign)

1. **Homepage does not match the brief:** headline is "Discover what
   your research is missing", not "Every answer has a blind spot";
   no question input on the homepage — a first-time user must find
   "Start research" and then a form. No example prompts on the hero.
2. **No guided flow:** `new-research` is one long form (goal,
   questions, URLs, pasted text) with no steps and no templates.
   A beginner gets no scholarship/college/job/scheme question sets.
3. **No Simple/Research view:** reports open straight into the
   technical dashboard (coverage %, matrix, graph). Plain-language
   "what's missing / what to do" is buried in gap cards and actions.
4. **Coverage % is unexplained in place:** its denominator
   (questions checked) and keyword-overlap method are not stated on
   the report itself.
5. **Progress is honestly vague:** analysis shows one spinner and
   "Waiting for the complete backend response" — correct (no fake
   stages), but the prompt's staged messages must NOT be faked;
   keep the honest single state and say why.

## Genuinely missing (do not claim otherwise)

- **No semantic coverage:** paraphrases miss (e.g. "eligible" vs
  "open to"; renewal phrased as "continue receiving support" — the
  synonym table is small). No embeddings, no claim extraction.
- **No PDF/document upload, no internet search, no claim-level
  provenance offsets.** The UI must keep saying so; adding a fake
  upload/search button would break the honesty rules.
- **No backend persistence, re-check/diff, saved-investigation sync,
  follow-up assistant, multilingual explanations, or report export
  beyond JSON/print.** Export is JSON + print only.
- **No different-year conflict suppression:** numeric/stance
  conflicts do not compare applicable years, so two statements from
  different cycles can flag as "possible" (labelled possible, never
  adjudicated — acceptable, but the rationale must say so).
- **No source-date extraction beyond meta/JSON-LD/`<time>`:**
  JS-rendered pages yield no text and no date; freshness is metadata
  only.
- **Sample data is fictional scholarship only** — one demo scenario,
  not the multi-scenario journey in the brief.

## Critical functional issues

- None found that breaks the core run: a live analysis with URLs +
  pasted text, a failing source, and a contradictory pair all flow
  through the same validated path. Known non-critical: rate limiter
  resets on container restart/sleep; backend sleep greets a cold
  judge with a platform wake page (mitigation: wake first, stated in
  submission pack and README).

## Security concerns (checked, not assumed)

- Secrets: backend-only env, never in frontend code or responses
  (health reports a boolean). No key found in repo.
- Prompt injection: pasted text is data to the deterministic engine,
  never sent to Groq (only the goal is), so injected instructions in
  a source cannot steer findings. Groq output is questions only and
  is never quoted as evidence.
- SSRF: covered above; residual DNS TOCTOU documented in README.

## AI reliability limitations

- Keyword overlap favours precision over recall; a well-answered
  question phrased differently reads `not_found`.
- Synonym table is hand-maintained and small; adding pairs can only
  select sentences, never invent quotes, so expansion is safe but
  must be tested for false matches.
- Groq question proposals are ungrounded suggestions (goal only);
  they are labelled "derived" and are editable by the user.

## Priorities for this redesign (agreed order)

P0: preserve everything above; no framework/DB migration.
P1: homepage hero with real input + examples; guided steps +
  templates; Simple view (default) + Research view; coverage
  denominator explained in place.
P2: conservative synonym expansion (renew/continue family) with
  tests; conflict rationale wording (different-year caveat).
P3: nothing in this pass — no upload, search, persistence, or
  assistant until a real implementation exists.
