# GapLens QA + security audit — 31 Oct 2026

Auditor role: senior full-stack QA engineer and security reviewer.
Scope: the repo as of commit `03ca2bb` (dashboard on the real
`/api/analyze`), plus the fixes made during this audit (see §2).
Rule followed throughout: no test is reported as passed unless it
was actually run, and a test that could not reach its target is
reported as inconclusive, not as a pass.

## 0. Verdict in one paragraph

The core is honest and well-typed: strict Pydantic schemas, quote
validation, labelled sample data, and an SSRF design that re-validates
every redirect hop. The audit found one **critical crash**, one
**missed conflict class**, and two **missing controls** (rate limiting,
security headers), all fixed and regression-tested in this audit.
What remains is not a hidden bug but a set of documented limits:
no authentication, per-process rate limiting, a sequential fetch
fan-out with a 200-second worst case, and a VM resolver that lies
about DNS (see §4). Do not expose this backend publicly without
auth + a gateway rate limiter + an IP-pinned fetcher (see §4.3).

## 2. Findings fixed in this audit (critical first)

### A1 — CRITICAL: every transport error crashed with 500
`backend/app/fetcher.py` caught `requests.SSLError`, which does not
exist as a top-level attribute in this requests version
(`hasattr(requests, "SSLError")` is `False`; the class lives in
`requests.exceptions`). Python evaluates the `except` expression when
an exception arrives, so any SSL/proxy/connection failure raised
`AttributeError` inside the handler and FastAPI returned 500.
Reproduced live: `POST /api/fetch` with a nonexistent host → 500,
and `POST /api/analyze` with inaccessible URLs → 500 (stack trace
in the uvicorn log confirms the `except requests.SSLError` line).
Why existing tests missed it: mocked tests only raised `Timeout`
(which is handled first) or returned fake responses, never SSL.
Fix: `from requests.exceptions import SSLError` and catch that.
Regression test: SSL, connection, and proxy errors all return a
`failed` fetch result, never raise.
After fix, the same requests return 200 with `failed` /
`inaccessible_source_ids` correctly populated.

### A2 — HIGH: "Rs." amounts never produced a conflict
Two causes, both fixed:
(a) The money regex only knew ₹/$/€/£, so "Rs. 10000" vs
"Rs. 12000" produced no money value and no conflict — in exactly
the Indian scholarship context the demo uses.
(b) Worse, the sentence splitter broke on every period, so
"Rs. 10000" was split into "…fee is Rs." and "10000 per year…":
the fee sentence carried no number at all. Fix (a): money pattern
now includes `Rs.?` and `INR` (case-insensitive). Fix (b):
`_sentences` no longer splits after known abbreviations
(Rs., Dr., e.g., i.e., single initials). Quotes stay verbatim —
the splitter only chooses cut points, it never rewrites text.
Verified live after fix: Rs. 10000 vs Rs. 12000 → one possible
conflict, both quotes shown, labelled "possible", never a winner.
Regression test pins both fixes. Limitation left: lakh/crore
words ("Rs. 2.5 lakh") are still not parsed as money (§4).

### A3 — MEDIUM: no rate limiting (open proxy / expensive endpoint)
`POST /api/fetch` and `POST /api/analyze` were unauthenticated and
unlimited: 60 health + 30 fetch requests in the first probe all
succeeded, 0×429. Fix: `backend/app/ratelimit.py`, per-IP fixed
window — 60/min for fetch, 30/min for analyze, 429 with
`Retry-After: 60` beyond that. Health/sample/root are not limited.
Verified live on a fresh server: analyze 30×200 then 429; fetch
60 responses then 429. Limit stated honestly: per-process only,
resets on restart, does not share across workers, and does not
trust `X-Forwarded-For` (spoofable) — behind a proxy all clients
share one bucket until a trusted forwarding setup exists.

### A4 — MEDIUM: no security headers
API responses carried no `X-Content-Type-Options`,
`X-Frame-Options`, or `Referrer-Policy`. Fix: middleware in
`main.py` sets `nosniff` / `DENY` / `no-referrer` on all responses.
Verified live via headers. (The API is JSON-only, so these are
safe to set unconditionally.)

### A5 — LOW: whitespace-only pasted text became a ghost source
`min_length=1` let `"   "` through; the collector normalized it to
empty text, and the record counted as neither accessible nor
inaccessible (status `ok`, `text_length` 0, summary "no sources
could be read"). Fix: `PastedText` validator rejects blank text
with 422. The UI already filters blank texts, so no UI change
was needed. Regression test pins the 422.

### A6 — LOW (a11y): inputs had no accessible names; drawer leaked focus
`ResearchInput` used `<p>` field labels with placeholder-only
inputs (no `<label>`, `aria-label`, or `id`). The source drawer
had Escape-to-close and `role="dialog"`, but focus stayed behind
it and Tab could leave the panel. Fix: `aria-label` on every goal /
question / URL / pasted-text input, and drawer focus management
(focus moves to Close on open, Tab cycles inside the panel,
Escape closes, focus returns to the opener). Full screen-reader
testing was not possible on this VM (no browser AT tooling);
this is a code-level fix, not a certified a11y pass (§4).

## 3. What passed without changes (with evidence)

- **Schemas / malformed / oversized (12/12):** empty/short/null
  goal, no inputs, 21 URLs, 21 combined inputs, question >500,
  text >200 000, unknown field (`extra="forbid"`), wrong types,
  empty questions list, invalid mode → all 422, no crash, no
  traceback. Oversized fetch URL → 422 (Pydantic 2083 cap).
  Invalid JSON body → 422. Unknown route → 404, no traceback,
  no filesystem paths.
- **SSRF (live, 16 cases):** localhost, 127.0.0.1, 10.x, 172.16.x,
  192.168.x (via existing tests), 169.254.169.254, `[::1]`,
  0.0.0.0, credentials in URL, `example.com@127.0.0.1`,
  `metadata.google.internal` → all `blocked`, no text returned.
  Numeric encodings that a naive check misses — decimal
  `2130706433`, hex `0x7f000001`, octal `0177.0.0.1` → all
  `blocked` live (the resolver expands them to loopback and the
  DNS-resolution check catches them). Unsafe schemes (ftp, file,
  javascript:) → 422 from `HttpUrl`. Redirects: mocked tests prove
  a redirect to a private target (plain and numeric-IP) is blocked
  and the private URL is never requested (calls list = first URL
  only); see the live caveat in §4.1.
- **CORS:** evil origin preflight gets no `Access-Control-Allow-
  Origin`; `http://localhost:5173` gets exactly that origin.
  Credentials are off (`allow_credentials=False`), methods are
  GET/POST only. CORS_ORIGINS is env-configurable; `*` would still
  be dangerous with an unauthenticated fetch endpoint — do not set
  it publicly (see §4.3).
- **Secrets:** health with a real dummy key on :8002 reports
  `groq_configured: true` and the key appears nowhere in health,
  sample, or analyze responses (checked by string search).
  `.env` files are gitignored and untracked; `.env.example` files
  carry placeholders only. No secret in the frontend bundle
  (frontend env is `VITE_API_URL` only; grep confirms no key
  reference in `frontend/src`).
- **Error leakage:** 404/422 bodies contain only FastAPI's detail
  objects; no tracebacks, no `/home/` paths, no secret values.
  (The one 500 in this audit was A1, fixed; after the fix, no
  probe produced a 500.)
- **Analysis engine (live, pasted texts):** multi-source IDs
  S1…S3 in input order; missing question → `not_found` + gap +
  high-priority action; undated pasted texts → `undated` warnings
  (never guessed); single-source, stale-only, and undated-only
  gaps; engine-level stale test (2020-01-15 source → stale warning
  with `age_days` 2481 and a `stale_only` gap); every evidence and
  conflict quote verified as a substring of its source text
  (unit sweep: 0 unverified quotes). Demo analyze: mode
  `offline_sample`, all 3 sources `is_sample: true`, 1 conflict.
- **Groq / invalid AI JSON:** with a dummy key, Groq returns 401
  and the API falls back to template questions with the note
  "Groq question derivation failed; template questions used
  instead." and method `deterministic` — live on :8002. Mocked
  unit tests: bad JSON, wrong shape, HTTP 429, and timeout all
  return `None` from `derive_questions_with_groq`, never raise.
  Groq only ever receives the goal and only proposes questions;
  findings/quotes never come from the model (code inspection +
  the fallback tests). No Groq key → sample/template path, no
  crash (health `groq_configured: false` throughout the audit).
- **XSS / safe rendering:** no `dangerouslySetInnerHTML` or
  `innerHTML` in `frontend/src` (grep). A pasted payload
  (`<script>alert(1)</script><img onerror=…>`) round-trips through
  `/api/analyze` as JSON data only; rendering safety rests on
  React's escaping, which is the correct layer. Drawer external
  links use `target="_blank" rel="noreferrer"` and the URL comes
  from the SSRF-validated fetcher (http(s) only), never from
  pasted text (pasted sources have `url: null`).
- **Inaccessible sites:** 404 page → `not_found` (distinct from
  DNS `nonexistent` in code and in mocked tests); paywall/bot
  401/403/429 → `blocked`; non-HTML → `unsupported`; oversize
  page → `too_large` (mocked, at the 1 000 000-byte cap).
  Analyze with two inaccessible inputs returns both IDs in
  `inaccessible_source_ids` plus retry/replace actions — never
  silently dropped.

## 4. Remaining limitations (do not present these as passes)

### 4.1 Live probes that the environment blocked (inconclusive, not passed)
- **Redirect-to-private, live:** `httpbin.org/redirect-to?url=
  http://127.0.0.1…` returns 403 from httpbin itself ("Forbidden
  redirect target: internal address") before the fetcher ever sees
  a redirect, so the live call proves "blocked outcome" but not
  the fetcher's redirect check. The fetcher's redirect check is
  proved by mocked tests (private + numeric-private targets,
  redirect chain followed for public targets, >3 redirects fail).
- **True timeout, live:** `httpbin.org/delay/15` is invalid
  (httpbin caps delay at 10 s and returns 400 in 0.5 s), and the
  VM proxy fast-fails unroutable hosts (TEST-NET 192.0.2.1 returned
  `failed` in 0.9 s). So no live request actually exercised the
  10 s socket timeout. Timeout handling is proved by the mocked
  test (`requests.Timeout` → status `timeout`) and by the
  configured `fetch_timeout_seconds: 10.0`; a live slow-host test
  needs a host that accepts and then stalls, reachable through
  the deployment's proxy.
- **Nonexistent vs failed, live on this VM:** the VM's egress
  resolver returns a 198.18.x.x address for *every* hostname,
  including names that do not exist. The fetcher's DNS check
  therefore cannot fail here, and a nonexistent host returns
  `failed` (proxy/SSL error) instead of `nonexistent`. The
  `nonexistent` path itself is correct and mocked-tested; it
  will only surface under a truthful resolver. Do not demo
  "nonexistent" on this VM and expect it.
- **Browser UI walkthrough:** see §5.

### 4.2 Engine and product limits (by design, but state them)
- Token-overlap scoring is keyword matching, not understanding:
  paraphrases, synonyms beyond the small built-in map, and
  "Rs. 2.5 lakh" / "2.5 lakh" money words are missed; a question
  phrased differently from its sources can read `not_found`
  even when an answer exists in substance. The demo's scholarship
  questions are tuned to the demo texts; a judge's own URL may
  score lower. This is the top product risk, not a bug fixable
  in an audit.
- One numeric conflict per question (first kind with two values);
  later conflicts for the same question are not shown. Stance
  conflicts depend on a deny-cue window and can miss or
  misfire on negated phrasing.
- Freshness comes from meta/JSON-LD/`<time>` dates only. A page
  whose date lives only in body text is `undated`, and a wrong
  meta date is trusted as-is. Future-dated pages are not stale
  (negative age is not flagged).
- No persistence: runs are per-request only. No re-check/diff,
  no export, no auth, no multi-user separation in this layer.
  Pasted text is never stored, but fetched-page text lives in
  the worker only for the duration of the run.
- Validation drops unverifiable quotes, but gaps/actions are not
  recomputed after that drop (defensive path; engine quotes
  normally pass because they come from collected text).

### 4.3 Deployment limits (read before going public)
- **No authentication.** Anyone who can reach the API can spend
  its fetch/analyze budget. The in-process rate limiter (§2 A3)
  is not a substitute for gateway auth + a shared limiter.
- **Sequential fetch fan-out:** `/api/analyze` fetches up to 20
  URLs one after another at up to 10 s each — worst case ~200 s
  for one request, plus a 15 s Groq call for question derivation.
  There is no per-run time budget and no concurrency cap. A
  single worker can be tied up by a few slow-URL requests.
  Recommended next step: bounded parallelism (e.g. 5 workers)
  plus a per-run deadline, or an async job model.
- **SSRF residual (TOCTOU):** validation resolves DNS immediately
  before each request and re-validates every redirect hop, which
  closes the casual holes, but DNS can still change between
  validation and connection (rebinding). Full proof needs
  connecting to the validated IP with Host/SNI handling — a
  bigger change, documented in the fetcher module already.
- **No request-body size cap** beyond Pydantic field limits
  (200 000 chars per pasted text, 20 inputs ≈ 4 MB + JSON
  overhead). A reverse proxy `client_max_body_size` (or
  equivalent) is advisable in front of the API.
- **No structured logging / metrics** for fetch failures, Groq
  failures, or rate-limit hits — debugging a live demo failure
  means reading uvicorn stdout.
